# 技术原理与逆向记录

> 实测机型：联想小新 Air 14 2020（81YN，Lenovo XiaoXinAir-14ARE 2020），Win11 家庭版。
> 其他 IdeaPad / 小新机型接口同源，但数值和是否可用需自行验证。

## 1. 结论：固件只有三态，没有百分比

这台机器的 EC / 固件**没有「任意百分比充电阈值」接口**，只有三种状态：

- 普通充电（充满 100%）
- 电池养护模式（本机约 55%–60% 停充）
- 快速充电

联想官方对 IdeaPad 的口径也是「只有电池养护，没有充电阈值」；Vantage 里 75% / 80% 的「自定义充电阈值」是 ThinkPad 的功能，这台 IdeaPad 没有。网上那些改注册表 `ChargeStopPercentage` 的方案，本机连对应的 WMI 类和注册表项都不存在。

所以：

- **要稳定停在 60%**：用「硬件养护」模式，这是固件原生能力，最稳。
- **要 80% 之类的自定义上限**：程序用「到上限就开养护、低于下限就恢复充电」的软件方式维持，能把电量压在目标以下，但**不是稳定保持**——EC 会主动往 60% 放，所以会在「下限 ~ 上限」之间小幅充放。这是硬件限制。

## 2. 调用链

Vantage / 联想电脑管家的电源管理并不是私有魔法，走的是联想 ACPI 驱动：

```
Lenovo Vantage / 本工具
  → Lenovo ACPI-Compliant Virtual Power Controller (AcpiVpc.sys，服务 ACPIVPC)
  → 设备 \\.\EnergyDrv
  → IOCTL 0x831020F8
  → ACPI 方法 GBMD（查询） / SBMC（设置）
  → EC 字段 BTSM / LBTM / CDMB ...
```

## 3. IOCTL 细节

查询：

```
输入：1 字节 0xFF
输出：4 字节 GBMD
```

实测返回值：

| 状态 | GBMD | bit5 | 充电 |
|---|---|---|---|
| 普通充电 | `0x00120244` / `0x00120240` | 0 | Charging=True，约 15–26 W |
| 养护模式 | `0x00120066` / `0x00120062` | 1 | Charging=False，DischargeRate≈8–9 W |

所以 `(mode >> 5) & 1` 就是「养护是否开启」。

设置：

```
输入：1 字节
  3 = 养护开（BTSM=1）
  5 = 养护关（BTSM=0）
```

实测当前 shell 不是管理员，读写都能成功；万一你的机器拒绝，用管理员权限运行一次即可。

## 4. DSDT 拆解：为什么没有百分比参数

把本机 DSDT 里的 `SBMC` 方法体完整拆开后，它只按**模式编号**分支：

```
Arg0 = 0/1/3/5/6/7/8/9/10/11/13/15/16
```

分别去写 `CDMB`、`EDCC`、`BTSM`、`LBTM`、`BTSG`、`FCGM`、`EDC1`、`ICC1`、`LGB1`、`SSM1` 这些 EC 字段。**没有任何百分比参数，也没有 0x50(80)、0x4B(75) 这类常量**。

也就是说，固件根本没实现「充到 X% 停」这件事，不是被锁住了。

## 5. 试过的其他模式（都失败）

- `1`（`CDMB=1`）：没有停充，反而在养护模式下强制恢复充电（`GBMD=0x00120063`，`Charging=True`，约 8–14 W）。
- `6`、`7`、`8`、`9`：都没有停充。
- `SBSL` 这个「疑似阈值」的 ACPI 方法，在本机 DSDT、SSDT 以及所有动态 SSDT（SSD1–SSDJ）里都不存在；驱动的 SBSL IOCTL 对本机无效。

## 6. 开源实现印证

Linux 内核 `ideapad-laptop.c` 是同一套：

```c
#define GBMD_CONSERVATION_STATE_BIT 5
#define SBMC_CONSERVATION_ON  3
#define SBMC_CONSERVATION_OFF 5
```

ArchWiki 对 IdeaPad 的写法也是 `SBMC 0x03` 开、`0x05` 关。它同样只有布尔开关，没有百分比。

## 7. 实测：养护不是「停在当前电量」

94% 时打开养护：

```
Charging = False
DischargeRate ≈ 8–9 W
电量 94% → 93% → 92%（几分钟内持续下降）
```

它是向 60% 放电，不是保持当前值。这也是「自定义上限」只能做成浮动区间的原因。

## 8. 三种模式在软件里怎么实现

| 模式 | 实现 |
|---|---|
| 不限制 | 写 `SBMC 5`，关闭养护，正常充到 100% |
| 硬件养护 | 写 `SBMC 3`，打开固件养护 |
| 自定义上限 | 后台每 30 秒查一次：`pct ≥ 上限` 写 `SBMC 3` 停充；`pct ≤ 上限 − 回差` 写 `SBMC 5` 恢复。目标 100% 时始终 `SBMC 5` |

自定义模式的稳定性取舍：

- 上限 80%、回差 5% → 实际在 75%–80% 之间小幅充放
- 回差越大，充放次数越少，但下限越低
- 想长期插电省心，直接用「硬件养护 60%」

其他行为：

- 退出程序时，如果当前是自定义模式，会自动写 `SBMC 5` 恢复普通充电，避免留下 60% 限制
- 硬件养护模式退出后保留状态（与 Vantage 一致）
- 配置存在 `HKCU\Software\BatteryCeiling`；日志在 `%LOCALAPPDATA%\BatteryCeiling\log.txt`
